# Master DB v2 / Legacy Bridge\n\n## Scope lock\n\n- Supabase PostgreSQL is the canonical LIFE 2.0 Master DB v2.\n- Existing Google Sheets / Apps Script Master DB remains the Legacy Diagnosis Store.\n- Existing legacy records are not bulk-migrated for the Public Beta.\n- user_id is the single cross-module identity for MY LIFE / diag / Career / Edu / Legacy.\n- Auth identity is separated from internal user_id.\n- Legacy records are linked by an opaque source record key after verification.\n- Never auto-merge by name + phone.\n- Legacy data is READ_ONLY until field-level mapping is verified and approved.\n\n## Current known limitation\n\nThe actual production Master DB Apps Script and full Google Sheet schema are not present in this repository.\nTherefore this branch intentionally does not implement:\n- legacy field migration,\n- production legacy lookup,\n- automatic legacy account binding,\n- legacy write-back.\n\n## Production bridge target\n\nlife2-web -> life2-api -> Legacy Bridge -> existing GAS / Sheet (read-only)\n\nThe bridge may be enabled only after the actual GAS/Sheet schema and authorization model are inspected.\n\n## Public Beta\n\nLegacy migration is not a launch blocker.\n\nNew users: Auth -> canonical user_id -> Awareness/FACT/Action in Master DB v2.\nExisting diagnosis users: records remain where they are; linking can be added after verification.
